How your browser lays out text.

Every website you visit is silently running a text layout algorithm. This explorable lets you drag the width, switch languages, and watch one version stay opaque while the other one shows the measured pieces, line widths, and break decisions.

Aha moment Same text, same width, very different visibility

The browser panel wraps text normally. The Pretext panel exposes what the browser usually hides.

Core split Prepare once, layout many times

Preparing measures the text. Layout reuses that cached information every time the width changes.

The slider below is the whole lesson. Drag it and both panels update. The left side uses ordinary DOM wrapping. The right side uses Pretext, which means we can inspect the measured token widths, the exact line widths, and the cached arithmetic that powers the reflow.

Section 3

Why this matters beyond one paragraph

Once text measurement is cheap, you can ask layout questions without rendering first. That changes what a web interface is allowed to do.

  • Virtual scrolling Know text heights before items enter the viewport.
  • Shrinkwrap Find the tightest chat bubble width instead of living with CSS dead space.
  • Custom layout Route text around live obstacles or into custom columns with arithmetic instead of reflow loops.
